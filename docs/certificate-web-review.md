审查日期：2026-10-04。对象为当前工作区的发布候选代码。

最初审查确认 4 项功能缺陷及 1 项界面语义问题。**4 项功能缺陷现已修复并通过回归测试**；以下保留发现时的复现记录。证书选择器的界面语义问题单独保留，未改变现有 SNI 优先策略。本次修复未更新真机安装。

## 已复现问题

| 优先级 | 问题 | 实际影响 |
| --- | --- | --- |
| P1 | 站点更新回滚覆盖并发规则操作 | 停用规则接口返回成功，规则实际仍启用 |
| P1 | ACME 申请没有贯穿取消上下文 | 申请取消不生效，后台申请可阻塞服务停止 |
| P2 | 修改证书域名后仍为新域名提供旧证书 | 新证书申请失败时，客户端收到域名不匹配的证书 |
| P2 | Location 改写丢失路径挂载前缀 | `/app` 下的应用登录、跳转可能落入其他规则或返回 404 |

### 1. 并发回滚覆盖规则操作

位置：[站点更新失败回滚](../internal/webproxy/api.go#L256)、[规则修改的局部互斥](../internal/webproxy/api.go#L515)。

复现步骤：

1. 启动包含启用规则的站点。
2. 请求 A 把监听地址改为一个已被占用的本地端口。
3. 在 A 完成保存、等待重载时，请求 B 停用该站点的规则。
4. A 因端口占用返回 409 并恢复整个旧站点；B 返回 200，表示停用成功。
5. 最终配置中的规则仍是启用状态。

重复 5 次均得到 `update=409, toggle=200, restoredListen=true, enabled=true`。这是逻辑并发问题，Go race 检测没有报告内存数据竞争。

原因：只有规则接口使用 `mutationMu`，完整站点修改和启停没有使用同一套事务同步。完整站点回滚无条件写回之前的快照，覆盖了其他请求的变更。

修复方向：站点和规则的修改、删除、启停统一串行化保存、重载与回滚；若允许并行，应引入版本检查，回滚只撤销自己的变更。回归测试必须验证“返回成功的规则停用在配置和实际请求中均生效”。

### 2. 证书申请无法取消

位置：[申请流程](../internal/acme/manager.go#L385)、[DNS 传播检查](../internal/acme/manager.go#L160)、[停止管理器](../internal/acme/manager.go#L628)。

复现使用本地可信 HTTPS 模拟 CA，其目录请求由测试主动阻塞：

- `Obtain` 已进入网络请求后取消传入的 context，300 ms 后请求仍未退出。
- 通过 `Reload` 启动后台申请，再调用 `Stop`，300 ms 后 `Stop` 仍未返回。
- 只有解除模拟 CA 的阻塞后，申请和停止才结束。

原因：`ctx.Err()` 只在申请入口检查一次，随后 lego HTTP 客户端没有绑定该上下文；DNS 查询另用 `context.Background()`，传播等待也不响应取消。内部网络超时仍可能结束单次请求，但不等于申请的十分钟期限和停止取消生效。

修复方向：为 ACME 和 DNS 请求统一传递操作上下文，取消可中断 HTTP、查询和等待；对申请任务统一登记生命周期，停止后不得继续写入证书和状态。

### 3. 新域名收到旧证书

位置：[域名变更处理](../internal/acme/api.go#L226)、[SNI 匹配及磁盘加载](../internal/acme/manager.go#L696)。

复现：为 `old.example` 写入有效期 90 天的测试证书，通过真实证书更新接口把域名改成 `new.example`，模拟 CA 返回申请失败。随后查询 `new.example` 的证书，得到的证书 SAN 仍为 `old.example`，`VerifyHostname("new.example")` 失败。

原因：修改域名只清空状态与内存缓存，旧证书文件仍保留。SNI 匹配使用新的配置域名，加载文件时没有验证实际证书的 SAN，因此把旧文件用于新域名。

修复方向：根据实际证书验证域名覆盖范围；区分期望证书配置和当前已签发证书。申请期间的配置变更也应使用代际检查，避免旧申请结果被提交为新配置的结果。代际问题目前是关联代码审查发现，尚未模拟完整签发过程复现。

### 4. 路径挂载的重定向丢失前缀

位置：[Location 改写](../internal/webproxy/reverse.go#L394)。

复现：规则匹配 `/app`，开启去除前缀及 Location 修正，后端返回绝对地址 `http://backend/login`。代理只改写协议和域名，最终返回 `http://public.example/login`，没有恢复 `/app/login`。该跳转离开原规则的挂载路径。

修复方向：对明确指向当前后端、且位于该后端映射路径内的绝对 Location 做逆向路径映射，保持转义路径与查询参数；继续保留其他主机或不属于映射范围的跳转。

## 界面语义问题

位置：[TLS 选证书顺序](../internal/webproxy/server.go#L620)、[站点证书选择](../web/src/components/webservice/SiteDialog.vue#L19)、[留空提示](../web/src/locales/zh-CN.js#L501)。

当前实际顺序是“全局 SNI 自动匹配 → 站点所选证书 → 自签”。所以即使站点选了一张有效证书，只要全局 SNI 匹配成功，实际提供的仍可能是另一张。留空提示“使用自签名证书”也不准确，留空仍会先自动匹配。

隔离测试确认了这个顺序。它与代码注释一致，因此将其列为界面语义问题，而非断言当前设计必须采用指定证书优先。可把选择器标为“默认/回退证书”，留空显示“SNI 自动匹配，无匹配时自签”；若产品意图是明确绑定，则应调整优先级。
