# Tunnel 集成验证记录

基线为集成前同一工作区构建（HEAD `d639aab73280c025695b7bf8295b84bcea3bf294`）。测量环境为 macOS ARM64、Go 1.27.1；npm 10.9.4 使用 Node 22.22.1；前后均使用同一工具链、依赖与发布参数。

## 体积

Go 发布参数：`GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -tags adminweb -ldflags '-s -w -X main.version=size-check'`。前端使用 `cd web && npm run build`，统计 `internal/adminweb/dist` 全部文件逐文件 `gzip.compress(data, mtime=0)` 的总大小（Python 3，默认压缩级别）。

| --- | ---: | ---: | ---: | ---: |
| Linux x86_64 主程序 | 14,028,960 | 14,311,584 | 282,624（276 KiB） | ≤ 1 MiB |
| 前端 gzip 总量 | 391,770 | 401,840 | 10,070（约 9.8 KiB） | ≤ 50 KiB |

本次六项审查修复相对上一版集成额外增加主程序 28,672 字节（28 KiB）、前端 gzip 571 字节。最终测量仍使用上述基线、工具链和参数。

不捆绑 cloudflared，没有新增 Go/npm 依赖或安装包强制依赖。新增页面按需加载；新增 Go 模块、Vue 页面和组件文件均小于 400 行，测试独立组织。构建产生的嵌入前端资源已更新。

- 前端：8 个测试文件、27 项测试；生产构建。此前实际浏览器检查实例保存、路由保存、Token 模式的只读同步提示及默认 TLS 校验；本次增加云端变更预览、明确确认及失败保留、共享路由禁用的组件测试。
- `go vet ./...`、`go test -race ./...`。
- `VERSION=tunnel-validation ./scripts/build-all.sh`：Linux x86_64、ARM64、ARMv7、MIPS、MIPSLE 均构建成功。
- 模拟 API 与进程：云端配置及未选路径规则保留、域名更名、DNS 冲突与归属、限流/权限错误脱敏、创建/DNS/删除丢失响应、云端写入后本地保存失败恢复、任务重启中断、子进程就绪与崩溃重启、显式停止、Token 文件权限/清理及日志长度/脱敏。
- 站点专用入口：真实 IP、普通 TCP 伪造头、Basic Auth、IP 名单、限流、HTTPS 跳转与 Location、WebSocket、SSE、Socket 权限、站点删除冲突及停用后关闭入口。
- 配置：旧配置兼容由原有回归覆盖；加密往返、空 Token 更新保留原值、保存失败回滚、备份字段恢复并默认停用实例、并发状态落盘。
- 审查回归：改名再恢复保留 DNS、未选云端路径规则继续使用 DNS、旧清理记录不会阻挡部分成功恢复；云端源站变更需明确逐条确认，覆盖待删除路由、摘要过期、共享连接器、重复路由、凭据源站、保存失败和未选路由保留。
- 身份与状态：拒绝 Token 与 Tunnel ID/Account ID 不一致及无效 Token，启动、子进程和云端管理均检查；Token 单独接入提取 Tunnel ID；待清理路由显示待同步；Socket 创建失败显示目标错误，不影响其他入口，恢复后清除错误。
- 健康检查：旧边车文件一次迁入加密主配置、跨设备备份完整恢复、旧备份不会重新导入旧文件、无新流量时立即恢复探测、失败保存回滚并保持原探测器。

## 真机补充验证（2026-10-03）

已在 ImmortalWrt 25.12.2、Linux 6.12.103、x86_64 设备上部署 `tunnel-validation` 构建，安装并校验官方 cloudflared 2026.9.3。配置、站点代理及 Tunnel 的 116 项顶层测试在设备上全部通过；设备测试为无 CGO 的测试可执行文件，本机竞态检查结果见上文。

使用独立临时配置验证实际管理接口、Token 身份及脱敏、官方子进程启动参数、Token 文件和 Socket 权限、崩溃重启、显式停止及清理、加密备份恢复后默认停用、健康检查恢复及重启持久化。另验证原 0.3.5 加密配置可以启动、正式服务重启保留配置和密钥，以及 56 个嵌入前端资源与当前构建逐文件摘要一致。详情见 [真机验证记录](tunnel-device-validation.md)。

## 尚需真实环境验收

没有使用有效 Cloudflare 凭据。设备上的官方 cloudflared 使用格式正确但无效的测试凭据；其进程运行与连接未就绪状态分别验证。云端创建、路由/DNS 同步及失败恢复仍使用模拟 API，未创建公网资源。

仍需在真实 Cloudflare 账号下验证公网访问及源站证书，并在 ARM64、ARMv7 设备上运行官方 cloudflared。本轮浏览器因管理后台自签证书报 `ERR_CERT_AUTHORITY_INVALID`，未完成真机页面交互检查；HTTPS 接口及静态资源检查通过。MIPS/MIPSLE 仅验证主程序交叉构建，Tunnel 功能保持未验证提示。
