# PVE 路由器实测及样式修正

首次验收 2026-10-13，最终复核 2026-10-14。目标为 **192.168.199.7**，当前已安装并运行 **0.3.7-lucky-pve-test3**。LuCI 的“服务 → andey-Proxy”入口已出现，procd 服务运行中，已设置开机启动。管理地址：**https://192.168.199.7:16606**。已用用户修改后的管理密码验证登录，验收文档不包含密码。

本轮使用当前工作区源码构建测试版，未提交、推送或发布。目标为 ImmortalWrt 25.12.2、Linux 6.12.103、x86_64，QEMU Q35/ICH9，2 vCPU、约 474 MiB 内存。安装采用仓库 OpenWrt 的二进制、init/UCI、LuCI 页面、菜单、ACL 和翻译文件直接部署；该机使用 APK，**没有安装 IPK、没有登记为 APK 包，也没有完成原生 APK 打包验收**。

## 功能实测

首先在该虚拟路由器上运行独立实例，通过 SSH 隧道访问。业务对象和三家 DNS 服务端模拟器均运行在路由器上；未使用生产 DNS 凭据。随后安装系统服务，使用持久配置目录 `/etc/andey-proxy` 和独立加密密钥 `/etc/andey-proxy.key`。

| 项目 | 结果 |
|---|---|
| DDNS 三家 | 阿里云、Cloudflare、DNSPod 实际适配器各完成 A/AAAA 写入本机模拟接口；强制漂移修复、同 IP TTL 更新通过 |
| DDNS 控制 | 记录独立启停、陈旧版本 409、双栈部分失败及恢复通过；浏览器启用/停用任务成功；实际 br-lan IPv4 来源读到 192.168.199.7 |
| Web 服务 | 实际反向代理响应体超过 100 KiB，自定义未匹配响应、健康检查配置、无效配置失败回滚通过 |
| 防护中心 | 策略热更新拦截正常和未匹配 Web 请求、新 TCP、同一 UDP socket 后续数据；恢复后重新回显；管理入口可访问；引用中的策略拒绝删除 |
| 全局 UA 与封禁 | 命中 UA 拒绝，其它 UA 允许；临时封禁解除和自动到期恢复通过 |
| 证书 | PEM 导入、失败替换保留原证书；替换期间 40 次并发 TLS 请求成功，客户端验证证书及 pve.example.test 域名；重启后替换证书仍可服务 |
| Linux 指标 | CPU、内存、br-lan 计数/速率及历史取得真实数值；10 秒有界 CPU 负载期间采样约 32.80%、52.45%、20.72%；30 次并发代理请求完成，程序 RSS 约 20 MiB（该阶段观测值，不是性能上限） |
| 备份与进程重启 | 加密备份导出/恢复保留新字段、引用和健康检查，并撤销旧管理会话；实际程序重启后配置、导入证书、TLS/TCP/UDP 恢复。运行内存历史和计数按约定清空 |
| 安装后服务 | LuCI 显示“运行中 / 已启用”，版本文件及二进制一致；HTTPS 证书指纹与 SSH 日志一致，SSH 端点的 TLS 域名校验及新密码登录通过，五模块接口可读 |
| 网络与防火墙 | /etc/config/network、/etc/config/firewall 的 SHA-256 与测试前一致；未创建 WAN 放行规则 |

完整首轮脚本记录 73 次符合预期的认证 API 调用，补充备份/重启等脚本 25 次；最终系统服务另完成 12 次认证调用。预期的 400、409、500（模拟 IPv6 来源失败）和恢复后的旧会话 401 属于验证内容。没有把所有响应都描述为 200。

## 用户截图发现的问题及修正

用户指出总览上半部浅蓝、旧卡片白色，以及网络流量图左侧数字被挡。再次目视检查又发现手机展开 Web 图表时卡片被撑宽，外层隐藏溢出掩盖了问题。

| 问题 | 修正 |
|---|---|
| 新旧卡片背景混用 | 映射 Element Plus 的卡片、表格、弹层和填充令牌；同类卡片统一 #edf5fb，输入区域统一使用更浅的表面色；边框及阴影来自共享令牌 |
| 固定宽度坐标轴裁切长数字 | 按实际字体测量格式化刻度，给文字、刻度线及间距分配宽度；CPU、网络及站点左右轴共用计算 |
| 图表边缘与图例 | 增加边缘留白；网络速率补齐 GB/s、TB/s；图例在窄屏换行 |
| 后端地址标签从左侧被截断 | 对标签内容做末尾省略，保留开头，完整地址通过标题/提示展示 |
| 手机非空图表撑宽 Web 卡片 | 外层使用 minmax(0,1fr) 网格，卡片/图表设 min-width:0；共享 page-grid 同步收紧；移除主内容区域隐藏横向溢出的掩盖方式 |

最后检查了概览、DDNS、Web 服务、证书、防护、转发、隧道、日志、通知和设置共 **10 个页面**，分别在 **390px、1440px** 下测量。同类卡片实测背景均为 `rgb(237,245,251)`；20 组页面均满足主内容容器 `scrollWidth == clientWidth`。同时检查有真实请求数据的手机站点双坐标轴图：图表宽 310px，左/右轴分别位于屏幕内，主内容宽和实际滚动宽均为 390px，图例能换行。控制台未见 error。

UI 截图来自同机、同一二进制的 SSH 隔离审查实例；样式审查副本的业务监听与用户系统服务分离。自动浏览器无法直接打开设备的自签 HTTPS 页面，未绕过证书警告。系统 HTTPS 服务另通过 SSH 指纹对照、TLS 主机名验证和认证 API 验证；用户已在自己的浏览器完成实际登录及改密。

## 留存与边界

- 当前使用系统服务 `/etc/init.d/andey-proxy`，二进制 `/usr/bin/andey-proxy`，持久配置和证书在 `/etc/andey-proxy`。**文件级迁移必须一并保留旁边的 `/etc/andey-proxy.key`**；仅复制目录不能解密配置。口令加密的 API 备份独立于这个设备密钥，但不打包证书私钥材料。
- 最终复核后已停止同机的临时样式审查实例，18843/18944 审查监听已关闭；安装服务继续监听 16606，演示模拟器继续监听回环 18849。
- 升级前留有仅 root 可访问的备份：`/root/andey-proxy-test-backups/20261013-style/`，包含旧二进制、配置/密钥/证书运行目录；没有修改用户的新管理密码。
- 安装时复制的三家服务商、双栈任务、站点和转发均是明确标记的测试对象，业务默认停用。模拟服务端仅监听回环地址，位于 `/tmp/andey-pve-test/helper`，用于演示测试，重启虚拟机后不会自动恢复。正式功能不依赖这个模拟器。
- 完成了程序进程重启，**没有重启虚拟机验证开机启动**；“已启用”是 procd/init 状态与启动链接验证。
- 尚未验证真实公网 DNS 写入、真实 ACME CA 签发、生产 Tunnel/WAN 可达性、真实手机或长期负载。此为 PVE 虚拟机实测，不代表实体路由器性能验收。
